# BBA 内部路线图

[English](../ROADMAP.md) · [Español](../es/ROADMAP.md) · [Português (Brasil)](../pt-BR/ROADMAP.md) · **简体中文**

更新于 2026-10-31。**2.0.0** 版本整合了传输、协议和隔离方面的修复；围绕声明式 schema 统一了 CLI/MCP；并新增十二项能力，没有增加额外的外部生产依赖。范围、预算以及不持久化机密的约束依旧。目标是：借助技能、本地 CLI/MCP 引擎、证据、受控评估和获授权的试点，开展可复现的 Web/API 研究。必须区分自动化检测、智能体辅助的调查和线索。无论版本号还是一次成功的实验运行，都不能保证在任何目标上发现严重 bug。

## 范围与发布标准

项目从可重复的契约和一个双账号的存在漏洞/已修复 BOLA 实验环境起步，随后加入了带持久化 SQLite 检查点的范围受限 HTTP 执行器、离线的 HAR/OpenAPI/REA 导入、隔离的 Chromium 抓取、语义检查、扫描器候选项导入、MCP 以及一组冻结的评估集。已文档化的漏洞类别并不自动意味着已实现。需要在政策之外采取行动的测试保持为不确定。REA 负责客户端产物；有权检查某个产物并不授权去联系它的后端。

发布标准要求：强制性的范围和机密检查通过，已修复的变体不得被确认，报告可复现，安装/诊断/取消/恢复/导出可用，并且没有任何适配器会逃出已授权的目的地或预算。效果无法被约束的工具只能用于实验或仅导入。实验指标不应外推到所有系统。试点会记录范围、覆盖、限制和证据；发现 bug 不是发布条件。

## 时间线与证据

- **1.0.0 试点，2026-10-29：** 对内部获得授权的 DCS 网站仅用匿名、范围内的 GET 做了测试，不属于第三方赏金项目。六个页面的抓取发出了 6 个 GET，阻止了 366 个浏览器请求，未检测到泄漏。随后两次运行共发出 5 个 GET，并在 `/xmlrpc.php` 的 301 处停止。没有已确认的发现。WordPress 和 Elementor 的版本提示只是信息性候选项，并不能证明插件已过时。试点暴露了缺少重定向目的地保留以及可配置标识头的问题。
- **1.2.0 试点：** 报告了严格的 TypeScript、159 个测试和 36 个模块的构建。对 DCS 进行的第二次有边界试点发出四个公开 GET，阻止了 67 个范围外资源，未检测到 sink 泄漏或不确定的预留。该网站上没有测试表单、凭据、授权边界或 payload。公开网站的结果不能确立其安全性，也不代表存在公开的赏金项目。
- **1.3.0 JWT：** [Titan 文章](https://blog.faav.net/how-i-couldve-accessed-17-trillion-microsoft-records)促成了一项针对自有账号的签名完整性检查，它有别于验证错误线索和数据触达范围的估算。Swagger 路由或存档配置是候选项，绝非许可。记录的验证通过了 165 个测试和 37 个模块的构建，涵盖存在漏洞/已修复的实验环境、网络拒绝、恢复绑定、导入、MCP 清单和打包。没有对文章所述的服务进行主动测试。
- **1.4.0 已发表案例研究：** 案例清单、当前政策、导入的攻击面和一条历史线索，共同导出一个有边界的 JWT 候选项和一份五个部分的草稿。有歧义或被排除的候选项保持离线。记录的验证通过了 170 个测试和 38 个模块的构建。它没有复现原文章的影响。
- **1.5.0 MCP 与页面结构：** `setup-mcp` 预览、备份并注册一个离线优先的服务器；`inspect_web_page` 投影出链接、表单和脚本，不含值/查询；`page_view` 离线读取它们。DOM 路由不会扩大范围。记录的验证通过了 172 个测试和 39 个模块的构建，包括隔离的 Codex 注册和合成的 DOM 抓取。
- **1.6.0 案例档案：** 案例账本关联范围、政策审阅、攻击面、配置、执行和草稿。抓取和执行需要当前有效的声明和共享预算，在请求前预留动作文件夹，并在中断后阻止静默重复。记录的验证：175 个测试和 40 个模块的构建。此阶段没有对外部服务做主动测试。
- **1.7.0 恢复：** `campaign_resume` 检查 scope/surface/profile 是否一致，并只继续尚未开始的步骤；被中断的动作和不确定的预留会阻止不安全的重复。记录的验证：176 个测试和 40 个模块，新增请求仅限回环。
- **1.8.0 语义报告：** 发现分别说明问题、发现、证明、复现和修复，保留 `confirmed`、`not-reproduced` 或 `unresolved` 以及证据 ID。记录的验证：176 个测试和 40 个模块。
- **1.9.0 有边界的检查：** 新增模板算术、自有回调、与缓存相关的跨账号暴露、一次性竞态和跨源表单，具备精确的规则、负向对照、自有资源和五个部分的草稿。政策副本可以通过哈希与案例决定绑定，但其哈希并不认证政策或所有者的许可。记录的验证：**194 个测试，无跳过**，严格的 TypeScript，以及在合成回环服务器上 45 个模块的构建。

## 2.0.0 版本

在 1.9.0 基线之后有三个板块：

1. **安全、传输和协议修复（13 项）：** CLI/MCP 边界处的 `SafeError`；RFC 6265 的 Cookie 字符；双栈公网 DNS 固定和不完整响应检测；RFC 6901 数组索引检查；Win32/SQLite 事务锁；带外的 MCP `ping` 以及带 `AbortSignal` 的 `notifications/cancelled`；并发预算对的乱序释放；完整的 CSRF Cookie 处理；JWT 检查中的原生 JSON 类型；研究的 `requestHeaders`；等待前的截止时间检查；针对 Chrome 145+ STUN UDP 泄漏的 WebRTC peer-connection 冻结；路径中对 RFC 3986 `pchar`（`:`、`@`）的支持。
2. **结构与开发者体验（12 项）：** 带 `campaign|check|study` 分组和按命令帮助的声明式 CLI 命令注册表；无依赖的 schema，带 JSON Schema 投影和精确字段路径；共享日志以及交叉路由的证据/产物视图；安全的递归构建；Ubuntu/Windows 的 GitHub Actions CI；`producerVersion`；`--lang es|en`；范围路径前缀、`{param}` 模板和 `filter[id]`；Node `>=22.13.0`；Codex/Claude/Gemini 的 MCP 配置；原生 TypeScript 的 ZIP 打包器；带隔离的线性时间 HAR 投影。
3. **新检查、攻击面和证据（12 项）：** 在一次性资源上以前后状态进行语义变异/批量赋值；离线的 GraphQL 与 JS/SourceMap 导入以及 `graphql-check`；JWT `alg-none` 和 `expired-token`；OAuth `redirect_uri`；内存中的临时认证引导；不跟随的 3xx `Location` 分类；离线的 HackerOne/Bugcrowd/Intigriti/security.txt 政策导入，通配符需人工审阅；扫描器候选项计划；带保守 CVSS v3.1/v4.0 和脱敏 `curl` 的提交草稿；单连接 HTTP/2 竞态；Ed25519 密钥/签名/验证；带严格 CSP 的只读回环 HTML 检查器。

## 剩余局限

操作者必须核实当前政策、业务规则以及受控账号/资源，并在报告前审阅证明与影响。通用的 SQL/NoSQL/命令确认、针对内部目的地的 SSRF、其他类型的 CSRF 请求、缓存的因果归因以及其他竞态流程仍未解决。与负责产物/运行时分析的 REA 没有功能对等，也不保证在任意网站或应用上发现严重问题。实验证据不会外推到真实服务。如果要选择第三方赏金项目，需要有效的奖励计划、清晰的范围、测试账号、兼容的规则以及有边界的计划。发送报告需要用户的明确授权。
