# BBA 自主目标与工作流

[English](../HUNT.md) · [Español](../es/HUNT.md) · [Português (Brasil)](../pt-BR/HUNT.md) · **简体中文**

目标是从一个已授权的网站出发，发现其攻击面，生成并运行假设，用对照确认漏洞，记录证明，并留下可供漏洞赏金审阅的草稿。账号、规则和范围只需设置一次；框架会在这些限制内提出检查，无需手工列出预期的 bug。

## 当前实现

`hunt --scope scope.json --config hunt.json --out runs/hunt` 针对两个账号之间对私有字段的不当读取（BOLA）实现了这一点，可通过 CLI 或启用网络的 MCP 使用。技能根据服务和当前政策准备文件；`prepare` 离线启动一个案例。这是一条专门的路径；当没有账号或仅所有者可访问的规则时，并不要求使用它。

```json
{
  "schemaVersion": 1,
  "seed": "https://service.example/",
  "identityUrl": "https://service.example/api/me",
  "identityField": "id",
  "ownerField": "ownerId",
  "privateField": "privateNotes",
  "accounts": ["BBA_TOKEN_A", "BBA_TOKEN_B"],
  "boundary": "owner-only"
}
```

示例 URL 只是结构示意，并非目标。机密来自被引用的环境变量；`BBA_COOKIE_*` 同样支持 Cookie。请使用你控制的两个不同账号，且二者对被检查的资源没有共享权限。由操作者确立该字段仅限所有者访问；名为 `ownerId` 的字段并不能确立业务规则。范围包含精确的来源和路径，可能包含尚未访问的允许路径。发现过程不会扩大范围：外部的、被排除的、带查询的或无法表示的链接不会被访问。没有通配符，也不枚举他人的对象。

## 确认

1. 用每个凭据查询身份端点，并要求服务器返回互不相同的 ID。
2. 以两个账号从种子页面出发跟随 HTML 链接，遵守共同的范围、预算、间隔、超时、大小和截止时间限制。
3. 对于属于其中一个身份且带有已配置私有字段的 JSON 文档，生成一个假设。
4. 以匿名身份和另一个账号读取同一资源。只有匿名访问被拒绝，而第二个身份拿到了相同的所有者和受保护的值时才确认。
5. 写出结果、证据引用和报告。无效的会话、公开数据或不完整的对照绝不构成确认。

首次确认即停止，避免为同一个成因读取更多资源。已发现但未访问的链接仍是覆盖空白；一次正面的证明并不能解决其他类别。`scope.requestHeaders` 按来源添加绑定到环境的标识标记，且不持久化值。仅有 HTTP 200 或相同的响应体哈希是不够的。报告会关联响应、身份证据和受保护字段的摘要。所有权和机密性仍取决于操作者声明的前提条件。

## 产物

- `requests.jsonl` 在每次发送前同步意图，随后保存响应元数据以及脱敏后的身份/字段对比。数字 ID 把报告和请求关联起来。
- `hunt.json` 保存发现的攻击面、来源响应、假设、状态、已用预算、停止原因、限制和校验和。
- `report.md` 包含访问规则、前提条件、编号的复现步骤、行为者/资源、证据、观察到的效果、修复建议和分诊空白。

不保存凭据、Cookie 或原始私有值。获得授权的 URL 和字段名会被保留；请勿在其中放入机密。脱敏后的证据可以用测试账号复现，但它不是完整的流量捕获。哈希不认证作者。没有结果的尝试保留在日志中。Ctrl+C 会记录部分事实并以 130 退出。间隔等待之后会重新检查取消、截止时间和授权。`hunt` 不能自动恢复，也不会重试不确定的尝试。新的运行需要新的文件夹，并需要审阅已消耗的预算；静态的 `run/resume` 使用它自己的检查点机制。

## 覆盖空白

`hunt` 不执行 JavaScript，也不推断角色/租户；其基于 HTML 链接的生成器只覆盖 BOLA。其他路径请参见[语义调查](INVESTIGATION.md)、[Chromium 的 XSS/CORS](BROWSER-CHECKS.md)和[浏览器会话](SCENARIOS.md)。不存在通用的注入/SSRF 确认，也没有通用的业务规则推断。没有找到合适的资源可能不会产生任何假设，这并不是安全结论。这里没有自动提交、奖金保证、对线上项目的去重，也没有生产环境验证。

## 1.2 之前的历史审阅

此前 Claude 在范围/传输、抓取、导入、评估、持久化、CLI/MCP、打包和冻结评估方面的工作已经过审阅。预算/检查点、目的地隔离、具备来源追溯的导入器、按身份的浏览器隔离、受限的 MCP 以及 JS 打包被保留。BBA 增加了自主的假设生成；`evaluate-run` 现在把哈希匹配保留为 `needs-validation`，属性响应不同则为 `unresolved`。冻结评估第 2 版记录了零次确认和三次遗漏，而不是夸大检出指标。抓取不再把页面凭据转发到另一个来源，并在等待后重新检查取消/截止时间。构建会拒绝工作区 `dist` 或 `.build-test` 之外的删除目标，并拒绝链接。内部获得授权的 DCS 试点从未授权新的测试，也未完成第三方赏金试点。六个浏览器测试最初因缺少 Chromium 而被跳过；1.2 运行了完整测试套件以及对 DCS 的有边界公开试点。两者都不能证明对网络的广泛覆盖。
